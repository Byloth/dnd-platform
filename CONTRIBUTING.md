# Contributing

This project is documentation-first: the plan in [`docs/`](docs/00-README.md) says what is built and why, the
open questions live in the decision register ([`docs/17-open-decisions.md`](docs/17-open-decisions.md)) and every
phase has an execution plan (`docs/phase-<n>/`). Read the phase plan before changing anything in its scope.

## Setting up

Node 24 (`.nvmrc`) and pnpm. Then:

```sh
pnpm install
pnpm build                   # compile every workspace package (the CLI runs from packages/cli/dist)
pnpm lint && pnpm typecheck && pnpm test
pnpm validate:content        # every content package against the schemas
pnpm fixtures                # golden characters, play sessions, section trees and readable sheets
pnpm web:prepare-content && pnpm web:generate   # the static site
```

The pre-commit hook runs lint, typecheck and the test suite, and refuses anything under `content-private/`.

## Where things are

| Directory | What it holds |
|---|---|
| `packages/schema` | the content format: JSON Schemas (source of truth) and the generated TypeScript types |
| `packages/engine` | the pure rules engine: `loadPackages`, `validate`, `derive`, `explain`, `apply`, `undo`; no I/O |
| `packages/composer` | the sheet composer: computed sheet → section tree, the data every rendering starts from; pure |
| `packages/cli` | the `dnd` command: `validate`, `build`, `derive`, `fixtures`; the text renderer over the section tree |
| `packages/web` | the web application: Nuxt 4, client-rendered, static; runs entirely in the browser |
| `packages/content/srd51` | the SRD 5.1 base package, generated by `tools/import` with hand-authored mechanics in `tools/import/overlay` |
| `fixtures/` | example packages, golden characters (`expected.yaml`, `snapshot.json`, `sheet.txt`), play sessions |
| `content-private/` | copyrighted books transcribed by their owner: git-ignored, same format, never committed |

## Rules that are not negotiable

- **Content is data.** A rule that a feature needs goes into the content format as an effect kind, an effect
  field or a ruleset key, never into a code path for one entity. Edition-specific numbers live in
  `ruleset.yaml` ([`docs/phase-0/07-ruleset-switching.md`](docs/phase-0/07-ruleset-switching.md)).
- **The format is frozen at `formatVersion: 0`.** Additive optional fields are fine and are recorded as such in
  [`docs/phase-0/inventory/authoring-review.md`](docs/phase-0/inventory/authoring-review.md); a rename or a
  removal waits for v1 and its migration script.
- **Only the SRD is public.** Text from any other book never enters the repository, not in fixtures, tests,
  commit messages or issues ([`docs/phase-0/06-private-packages.md`](docs/phase-0/06-private-packages.md)).
- **Golden files are reviewed, not regenerated.** `pnpm fixtures --update` after reading the diff; a snapshot
  change is a change of behaviour and the commit message says which.
- **Decisions go through the register.** A choice that shapes the product is a `DEC-nn` entry, taken by the
  project owner; code follows the register, not the other way round.

## Changing content

The SRD package is generated: edit `tools/import/overlay/<entity-id>.yaml` and re-run the map stage
(`node tools/import/src/map.ts`), or edit both the overlay and the generated file identically. Every entity
validates with `pnpm validate:content`; mechanics are proven by a golden fixture
([`docs/content-authoring.md`](docs/content-authoring.md)).

## Commits

Conventional commit subjects (`feat(engine): …`, `fix(cli): …`, `docs: …`, `test(play): …`), one topic per
commit, the reason in the body. Milestones are tagged by the owner; nothing is pushed by tooling.
